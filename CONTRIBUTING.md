# Contributing

Thank you for considering a contribution to Open Accessible Reading Layers (ORL).

ORL is an accessibility-focused public-good project. We especially welcome contributions that improve interoperability, accessibility, standards alignment, testing, documentation, and the clarity of the support-layer model.

## Before contributing

Please keep these principles in mind:

- reader control comes first;
- the underlying publication must remain usable without ORL;
- no critical meaning should depend only on color, imagery, or icons;
- accessibility claims should be tested rather than assumed;
- ORL should prefer open standards and portable data over proprietary lock-in;
- personal reading data should remain local/private by default unless a user explicitly chooses otherwise.

## Ways to contribute

Useful contributions include:

- implementation work;
- JSON Schema and validation feedback;
- EPUB / Readium integration;
- accessibility testing;
- screen-reader and keyboard testing;
- specification review;
- documentation;
- test fixtures;
- standards research;
- reader/user research;
- issue reports and reproducible bugs.

## Development direction

The current V0.1 scope is deliberately narrow:

1. DRM-free EPUB;
2. a separate ORL JSON sidecar;
3. People / Characters;
4. Timeline / Chronology;
5. Re-entry Context;
6. spoiler-safe progressive disclosure;
7. a Thorium Web / Readium reference reader;
8. local-first desktop compatibility.

Please avoid expanding a pull request into marketplace, accounts, DRM, social features, PDF, or cloud-sync work unless there is already an accepted issue for that scope.

## Contributions and licensing

Unless you explicitly state otherwise, contributions submitted for inclusion in this repository are provided under the Apache License 2.0, consistent with Section 5 of that license.

## Accessibility-related changes

For changes affecting user interface or interaction, please describe:

- keyboard behavior;
- screen-reader semantics;
- focus behavior;
- visual-only information and its text equivalent;
- zoom/reflow behavior where relevant;
- any accessibility testing performed.

## Conduct

Please follow [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).

## Questions

If the project is still early and no appropriate issue template exists, open a clear GitHub issue describing the problem, proposed change, and why it belongs in ORL.
