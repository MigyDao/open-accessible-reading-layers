# ORL beta.4 — native scrolling for compact EPUB reading

## Acceptance evidence and diagnosis
Miguel's installed beta.3 screenshots on 17 November 2026 confirm readable dark-mode prose (#7) and working library scrolling (#8), but show that The Water Line uses two-column paginated text at full width and a single clipped column when its Windows window is narrowed. A wheel scroll cannot advance the page because the embedded Thorium/Readium reflowable EPUB renderer is deliberately in **paginated** mode, with reading progression reached through page navigation. The outer .reading-surface's overflow:hidden keeps the reader container bounded and is not the root cause.

## Repair
Rather than forcing CSS overflow on nested Readium iframe content, observe the actual reading-surface width and request Readium's normal Redux setScroll action when its width drops below 840px. This includes narrower available space caused by the separate Reading Support side panel. On widening, restore the previous mode if this session's change was automatic. A visible ORL toolbar mode toggle switches between Scroll view and Page view, and manual choices take priority over the current automatic switch. Fixed-layout books are exempt. Readium remains responsible for layout, wheel/touch/keyboard scrolling, settings persistence and locator reporting.

## Data safety and acceptance boundary
No local data/state migrations, book reimports, overrides of publication CSS, changes to ORL anchors, or editor expansion. Existing per-book ThStoreProvider persistence and native saved reading locators remain in place. When closing the app while narrow, scroll mode may be retained on a later wide relaunch; the explicit mode toggle handles that case. Reading Support stays a side panel.

No new optional automated suites or computer-use GUI checks were added. GitHub compile/installer evidence does not prove native reading behavior. Manual user verification: wide two-column pages, narrow scrolling to the following text, support-panel narrow case, return to wide pages, explicit mode toggle, saved position after restart, and personal entry editor access. Issue #9 remains open until confirmed by Miguel. The larger author workspace is tracked as an **unapproved post-V1 proposal** in #10.

## Beta.5 follow-up — beta.4 scrolling regression
Miguel's manual beta.4 acceptance reported intermittent wheel scrolling, bottom text cut off in shorter windows, and no easy previous/next chapter buttons. Beta.4 invoked only `dispatch(setScroll(...))`, updating Thorium's Redux/UI flag without submitting the layout preference to the actual Readium EpubNavigator. Consequently, the Scroll view label could diverge from the real paginated EPUB renderer. Thorium Web 1.6.0's native `StatefulLayout` first awaits `submitPreferences({scroll})` and then mirrors `getSetting("scroll")` to the store.

Beta.5 applies that navigator-first sequence, serializes mode requests and waits for the reader-ready state. The actual reading surface is observed for width <840px or height <600px, including the space occupied by Reading Support. A manual selection takes precedence over the current session's automatic switch. Thorium's supported `ThLayoutUI.stacked` style for reflowable scroll reading keeps its **existing next/previous chapter footer controls** in normal layout instead of hiding them in a hover-only overlay. EPUB frames/DOM are not force-scrolled; publication scripts and data protections are unchanged.

Manual acceptance (Miguel only): resize width and height separately, try wheel over the prose, reach every line near the bottom, navigate with visible footer chapter buttons, return to Page view, preserve reading location, then repeat with the Reading Support side panel open. Source compilation/installer packaging does not constitute native GUI verification; no new optional automated tests, GUI automation, or data migration.

## Beta.6 — independently visible chapter navigation

After installing beta.5, Miguel reported improved reading but **no visible option to proceed to the next chapter in Scroll view**, except reopening Table of Contents. The beta.5 source only set Thorium's stacked layout, expecting its internal footer to appear. No ORL-controlled navigation buttons existed. This was an unverified assumption, not a confirmed repair.

Beta.6 adds a dedicated ORL **Previous chapter / Next chapter** nav row *outside* the embedded Thorium reading surface, below the main reader body and accessible in both narrow and short Windows windows. It displays only while Scroll view is enabled for a reflowable EPUB. The buttons use the book's EPUB reading-order links and Thorium/Readium's own `useEpubNavigator().goLink(new Link({href}),false,callback)`, the same underlying navigation API the Thorium footer uses. They never synthesize a new reading position, modify EPUB bytes or bypass the existing positionStorage/ORL gating callback. They are disabled when the navigator is loading, no current link can be matched, or the requested boundary does not exist. Current position is resolved from ORL's live/saved locator href against the publication reading-order hrefs (canonicalized relative to the opened manifest URL), or Thorium's 1-based progression index when needed. The non-spoiler "Section X of Y" position indicator reflects EPUB spine/reading-order sections; some EPUB files may group multiple semantic chapters into one resource.

The nav is in a normal layout row with persistent keyboard-reachable native buttons, not Thorium's hover-only footer. The reader body remains a flex child with min-height:0 and therefore takes the remaining viewport after the nav row; the support panel remains alongside the reader, not floating. Page view, theme, font settings, imported books, current position persistence, stored personal ORL packages, support reveal eligibility and JSON compatibility are unchanged.

Manual acceptance (Miguel): install beta.6 over beta.5 after preserving backup, open The Water Line in Scroll view, observe fixed ORL nav at bottom in maximized/narrow/short windows and when Reading Support is open, use Next/Previous to move across reading-order sections and verify the new location/progress, reach both first/last boundaries, switch to Page view and confirm the added nav disappears, reopen the book and ensure original data/settings persist. This is *not yet validated on installed Windows*; build and package results are separate from Miguel's user acceptance. No new optional automated suite or GUI computer-use was added.
