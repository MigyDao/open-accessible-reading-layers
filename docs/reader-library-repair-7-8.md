# Beta.3 — readable EPUBs and reachable library controls

## Installed beta.2 diagnosis (17 November 2026)

Issue #7 was reproduced in the actual Windows WebView with the existing imported Water Line copy and saved preferences. The saved reflow theme was `auto`, following the system dark scheme. Inside the publication iframe, Readium had set `--USER__textColor: #FEFEFE` and `--USER__backgroundColor: #000000`, but prose still computed to `rgb(0, 0, 0)` over a transparent document. The surrounding navigator surface was black.

WebView security logs explicitly blocked Readium's generated `blob:http://tauri.localhost/...` stylesheets and navigator script, plus the EPUB's `http://orl.localhost/<book>/EPUB/styles.css`, under the desktop CSP. Thus the variables existed without the styles that consume them. The original EPUB CSS does not specify foreground/background colors. This was a resource-policy integration error, not corrupted prose or an ORL layer issue.

The desktop CSP now permits blob scripts/styles generated by the trusted Readium navigator and styles from the app-only publication protocol. It still prohibits arbitrary remote script/network origins and JavaScript string evaluation. Native sanitization still removes publication scripts, event handlers, external references and embedded interactive content; only manifest-listed resources of app-managed EPUB copies are served. No EPUB source or per-book preferences are rewritten. This fixes the rendering pipeline rather than imposing one theme or overriding prose colors.

Issue #8 was reproduced before entering a book: Thorium's global reader stylesheet applies `overflow: hidden` to both `html` and `body`. At a 697px viewport, the library body was 1005px tall, and card controls extended to 863px. Wheel scrolling could not reach them. Keyboard focus could move the hidden document, explaining why accessibility controls existed while normal pointer navigation failed. The cover was also deliberately decorative rather than actionable.

Library pages now own a viewport-height vertical scroll container, with native wheel/keyboard/scrollbar support. Covers are native named buttons; Continue reading buttons include the book title in their accessible name. Returning through ORL's Library button restores the library scroll position and focuses the relevant saved-book button. Opening these controls uses the existing `open_book` command, not import.

The library identity remains the EPUB byte hash. Reimporting identical bytes already reuses the same record; the bundled demo and separately generated EPUB can legitimately have different archive bytes despite the same publication identifier. Existing copies, associated sidecars, progress and preferences are retained separately. No deduplication migration or data deletion is performed.

Reading Support remains the existing side panel. No floating widget, new automated test program or unrelated reader refactor is included.

## Upgrade and focused acceptance

Close ORL and back up `%APPDATA%\com.migydao.orl` and `%LOCALAPPDATA%\com.migydao.orl` before updating. Keep the beta.2 installer. Install beta.3 over the same destination; do not uninstall, clear storage or remove user data. The app identifier, storage keys, JSON formats and publication identifier/anchors are unchanged. Rollback is reinstalling beta.2 while retaining the backups; beta.2 still has these known defects.

Check the installed beta.3 at a short window height: scroll the library to the saved controls, open an existing entry, confirm immediately readable prose, switch light/dark/sepia and text size, return to the library, then reopen without import. Confirm saved location/settings after relaunch. Reading Support should still open beside the reader. Record only checks actually performed; compilation alone is not functional acceptance. The remaining V1 acceptance stays with Miguel, and existing browser CI/branch protection remain in effect.
